# Text File Reading and Writing

Text file input and output appears simple, yet is a freuent source of logic errors, data corruption and subtle bugs in real systems.

> Primary reason is that text I/O is often treated as n informal operation, while in realisty it encodes assumptions about structure, encoding delimiters, and failure behavior.

In Modern C++, text I/O must be explicit about intent. The code should clearly communcate whether it is reading structured data, line-oriented records, or free-form text.

> AMbiguity at this level inevitably leads to fragile havior as requirements evolve.

## Opening Text Files Explicitly

The text files should be opened using clear, default semantics. If text is expected, avoid binary mode and rely on the standard text behavior of the platform.

```cpp
std::ifstream open_text(const std::string& path){
    std::if stream file(path);

    if (!file){
        throw std::runtime_error("Failed to open text file");
    };

    return file;
}
```

## Line-Based Reading as a Safe Default

Line-based reading is the safest and most predictable approach for text files.

```cpp
#include <fstream>
#include <string>

void read_lines(const std:string& path){
    std::ifstream file(path);
    std::string line;

    while (std::getline(file, line)){
        // process complete line
    }
}
```

This pattern guarantees:

- Each iteration processes a complete logical record
- Whitespace is preserved within lines
- Failure conditions are explicit

For config files, logs and structured text, this should be the default approach.
