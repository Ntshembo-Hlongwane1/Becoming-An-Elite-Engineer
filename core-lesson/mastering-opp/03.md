# Modern OOP Features in Modern C++

## Initializer Lists

**Initializer lists** is a feature that defines how objects are constructed and brought into a valid state. Plays a critical role in performance, correctness and design clarity.

### What Are Initializer Lists

An **initializer list** is a list of expressions used to initialize class data members and base class subobjects **before the construtor body executes** 

**Syntax**

```cpp
ClassName::ClassName(parameters)
    : member1(value1),
      member2(value2),
      member3(value3){
        // Constructor body    
    }
```

**Key characteristics**

- Inialization occurs **before** the constructor body runs
- Members are initialized **directly** not assigned
- Base classes are intialized before derived class members
- Initialization order follows declaration order, not list order.

> Inializer lists define how and object comes into existence, not what happens after it already exists

### Why Initializer Lists Matter

#### Efficiency

- Without an intializer list:
    - Members are first default-constructed
    - Then reassigned inside the construtor body

- With an inializer list:
    - Mmebers are constructed **once**, directly with correct values

#### Const and Reference Members

**const data members** and **reference members**:

- Must be intialized at construction time
- Cannot be assigned later

> Inializer lists are therfore **mandatory** in these cases.

#### Base Class Initialization

Base classes must be fully constructed before the derived class body executes. Initializer lists are the only mechanism that allows passing args to base class constructors.

#### Correctness and Safety

Initializer lists:

- Prevent partially inialized objects
- Ensure invariants are established early
- Reduce subtle bugs related to uninitialized state

### Using Initializer lists

#### Basic Member Initialization

**Example: Inializing Member Variables**

```cpp
class Rectangle {
    int width;
    int height;

    public:
        Rectangle(int w, int h)
            : width(w),
              height(h) {}

        void display() const {        
            std::cout<<"Width:"<<width <<",Height:"<<height<<std::endl;
        }
}


int main(){
    Rectangle rect{10, 20};
    rect.display();
}
```

#### Inialization Order Rule

**Important Rule:**

Members are intialized in the order they are delcared in the class, **not** in the order they appear in the inializer list. 

> Violating this expectation can lead to subtle bugs.

**Best practice:** Always write intializer lists in the same order as member delcarations

#### Initializing Base Classes

When inheritance is involed, base class constructors must run first.

**Example: Base Class Initialization**

```cpp
class Shape {
    protected:
        int area;

    public:
        explict Shape(int a) : area(a) {}
}

class Square : public Shape {
    int sideLength;

    public:
        Square(int side) 
            : Shape(side * side), sideLength(side) {} 
}
```

**Key observations**

- The base class **Shape** is inialized first.
- Derived members are intialized afterward
- Constructor bodies execute last

### Common Pitfalls

- Initializing members inside the constructor body instead of the inizlizer list 
- Ignoring initialization order warnings
- Forgetting to initialize base classes explicitly
- Performing complex logic in initalizer expressions

### Best Practices

- Always prefer intializer lists over assignment
- Initialize members in declaration order
- Use initalizer lists for all constructors, even trivial ones
- Keep intializer expressioins simple and dertministic
- Combine intializer lists with RAII principles

## Constructors and Destructors (Default, Copy, Move)

In C++ constructor and destructors define the the complete **lifecycle of an object**. They are the primary mechanism through which objects **acquire** and **release resource**, **establish invariants** and **interact safely** with the surrounding system


### Constructors and Destructors Overview

#### Constructors

A **constructors** is a special member function that is auto invoked when an object is created. Its purpose is to initilize the obeject into a valid usable state.

**Key Properties**

- Same name as the class
- Has no return type
- Can be overloaded
- Executes exactly once per object lifetime

**Common constructor Categories:**

- Default constructor
- Copy constructor
- Move constructor

#### Destructors

A **destructor** is a special member function that is auto invoked when an object is destroyed. Its role is to release any resource owned by the object

**Key Properties**

- Same name as the class name but with a **~** sign before e.g ~ClassName
- Takes no parameters
- Has no return type 
- Called exactly once per object

Destructors are the backbone of **RAII (Resource Acquisition Is Initialization)**

### Default Constructors

A **default constructor** is a constructor that can be called with no args

**Example**

```cpp
class MyClass {
    int value;

    public:
        MyClass() : value(0) {}
}
```

### Copy Constructors

A **copy constructor** intilizes a new object as a copy of an existing object

**Canonical Signature:**

```cpp
ClassName(const ClassName& other);
```
**When it is invoked:**
- Passing objects by value
- Returning objects by value
- Initializing an object from another object

**Example**

```cpp
class MyClass{
    int value;

    public:
        explict MyClass(int v) : value(v) {}
        
        MyClass(const MyClass& other) : value(other.value) {}
}

int main(){
    MyClass object1(19);
    MyClass object2 = object1;
}
```

> **Important Note:** Shallow copying of owning resources leads to double-free bugs unless carefully managed

### Move Constructors

A **move constructor** tranfers ownership of resources from a temp (rvalue) object to new object.

**Canoncail Signature:**

```cpp
ClassName(ClassName&& other) noexcept;
```

**Why Move Constructors Matter:**
- Avoid expensive deep copies
- Enable efficient container reallocation
- Improve perfomance in modern C++

**Example**

```cpp
#include <vector>

class MyClass {
    std::vector<int> data;

    public:
        MyClass() = default;

        MyClass(std::vector<int>&& vect) 
            : data(std::move(vect)){}
}

int main(){
    std::vector<int> vec{1, 2, 3};
    MyClass obj(std::move(vec));
}
```

### Destructors

Destructors release reources acquired during construction 

**Typical Responsibilities:**

- Free heap memory
- Close filles
- Release locks
- Return system resources

**Example:**

```cpp
class MyClass {
    int data;

    public:
        explict MyClass(int v)
            : data(new int(v)){}

        ~MyClass(){
            delete data;
        }
}
```

> **Modern Advice:** Prefer the use of smart pointer over raw pointer to eliminate manual destructors


## Modern DesignRules

### Rule of Zero

If a class does not manage resources directly:
- Do not define destructor, copy, or move operation
- Let the compile generate everything

### Rule of Five

If you define one the following:

- Destuctor
- Copy constructor
- Copy assignment operator
- Move constructor
- Move assignment operator 

You likely need to define all five
