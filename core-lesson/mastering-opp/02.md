# Fundamental OOP Concepts

A class in C++ defines a user-defined type. It specifies:

- The data it owns
- The operation that can be perfomed on that data
- The access rules and preserves correctness

> A class is not an object itself, it is a description from which objects can be created.

## Defining a class

```cpp
#include <iostream>
#include <string>

class Car {
    public:
        Car(std::string brand, std::string model, int year) :
            brand_(std::move(brand)),
            model_(std::move(model)),
            year_(year) {}

        void print() const {
            std::cout << "Car info: "
                << brand_ << " "
                << model_ << " "
                << year_ << '\n';
        }

    private:
        std::string model_;
        std::string brand_;
        int year;
}
```
### What is an Object?

An object is a concrete instance of a class. Memory for an object is allocated when it is created, and its lifetime is governed by scope and ownership rules.

```cpp
Car myCar{"Toyota", "Camry", 2020};
```

### Access Specifiers and Encapsulation

C++ provides access specifiers to control visibility

- **public:** Part of the interface
- **private:** Internal representation
- **protected:** Accessible by derived classes

> Encapsulation is not about hiding data arbitrarily; it is about preserving class invariants and reducing coupling

```cpp

    public:
        explict Car(std::string vin) : vin_(std::move(vin)){}

    const std::string& vin() const {
        return vin_;
```

> Here, the VIN is immutable after construction, ensuring consistency

### Constructors and Destructors

Constructors establish invariants. Destructors release resources. Destructors in modern C++ are rarely used directly for memory management, as RAII types cleanup automatically

```cpp
class Logger {
    public:
        Logger(){
            std::cout << "Logger initialized\n";
        };

        ~Logger(){
            std::cout << "Logger destroyed\n";
        }
}
```

> Destructors are invoked automatically at the end of an object's lifetime.


## Inheritance and Its Forms in C++ (public, protected, private)

In C++ inheritance enables one class to derive behaviour from another, **but** Modern C++ treats inheritance as semantic tool, not code reuse mechanism.

> ISO C++ Guidelines mention that inheritance should primarily model substituability and polumorphic interfaces.

### What is Inheritance?

**Inheritance** is a mechanism by which a derived class extends or specializes the interface of a base class. The derived class may:

- Resuse behaviour
- Override virtual functions
- Extend functionality 

```cpp
class Base {
    // Base interface
}

class Derived : access-specifier Base{
    // Specialized behaviour
}
```

### Conceptual Types of Inheritance

C++ supports different types of inheritance, These descripbes how classes relate not access control

- **Single inheritance:** One derived class inherits from a single base class
- **Multiple inheritance:** Class inherits from more than one base class. This can be very powerful but with power comes great responsibility of care design to avoid unnecessary complexity
- **Multilevel inheritance:** A derived class becomes the base for another class, forming a chain.
- **Hierarchical inheritance:** Multiple derived classes inherit from the same base class
- **Hybrid inheritance:** A combination of the above often involving interfaces and matix

> Modern C++ strongly encourages limiting inheritance depth and avoiding complex hierarchies unless plolymorphism is essential

### Inheritance vs Composition

Modern C++ design favors **composition over inheritance**. Inheritance is encourages to be used only when:

- A true 'is-a' relationship exists.
- Polymorphic behavior is required
- The base class is designed for inheritance

Otherwise, composition provides:

- Lower coupling
- Clean and clear ownership
- Better readability 


## Encapsulation and Abstraction in Modern C++

These are engineering tools used to enforce invariants, control deps and define stable interaces.

### Encapsulation 

**Encapsulation:** is the practice of *binding data together with the operation that preserve its correctness*, while preventing direct external manipulation of internal state. It's true purpose is to enforce class invariants: conditions that must always hold true for an objects to remain valid. Encapsulation is achieved through:

- Access control (private, protected, public)
- Carefully designed member functions
- Explict ownership and lifetime rules

**Key properties of Encapsulation**

- Internal state cannot be arbitrarily modifed
- All mutations pass through controlled operations
- Invalid object state are prevented by construction

> Protects internal correctness

### Abstraction 

**Abstraction** is the processof defining what and object does while deliberately hiding how it does it. I modern C++ abstraction is expressed through:

- Abstract base classes
- Pure virtual functions
- Non-owning interfaces

> Managers external complexity

```cpp
class Shape {
    public vriatual Shape() = default;
    virtual void draw () const = 0;
}

class Circle final : public Shape {
    void draw() const override {
        std::cout << "Drawing circle\n";
    }
}

```

## Polymorphism and Its Types (Compile-time vs Run-time) in C++

**Polymorphism** enables a single interface to represent multiple underlying forms, this allows code to be written in a general, extensible, and reuseable manner. At the core polymorphism allows objects of different variants to be manipulated through a common base type while preserving type-specifi behavior.

### What is Polymorphism?

Ther term *polymorphism* originates from Greek, meaning **many-form**. In software it refers to the ability of different objects to respond to the same function in different ways. Polymorphism allows:

- Writing code against abstractions rather than concrete types
- Replacing components without modifying calling code
- Extending behavior via inheritance or templates
- Reducing coupling and improving maintaibility 

C++ supports two different kinds of polymorphsim:

- Compile-time Polymorphism (Static Polymorphism)
- Run-time Polymorphism (Dynamic Polymorphism)

### Types of Polymorphism in C++

#### Compile-time Polymorphism (Static Polymorphism)

**Compile-time Polymorphism** is resolved entirely during compilation. This form of polymorphism introduces **zero runtime overhead**. It is implemented using:

- Function overloading 
- Operator overloading
- Templates (parametric polymorphism)

```cpp
#include <iostream> 
#include <string> 
class Printer { 
    public: void print(int value) { 
        std::cout << "Integer: " << value << std::endl;
    }

    void print(double value) { 
        std::cout << "Double: " << value << std::endl; 
    }

    void print(const std::string& value) { 
        std::cout << "String: " << value << std::endl; 
    } 
};
 
    
int main() { 
    Printer p; p.print(10);
    p.print(3.14); 
    p.print("Hello C++"); 
}
```

**Key Notes:**

- Overload resolution happens at compile-time
- The selected function is based on the arg types
- Ambiguous overloads result in compilation errors

**Operator Overloading** allows built-in operators to work with user-defined types while prerveing natual syntax

```cpp
#include <iostream>

class Complex {
    double real;
    double imag;

    public:
        Complex(double r = 0, double i = 0) 
            : real(r), imag(i) {}

        Complex operator+(const Complex other) const {
            return Complex(real + other.real, imag + other.imag);
        }
}
```

**Design Guide**

- Operator should preserve intutive meaning
- Avoid suprising semantics
- Prefer named functions when intent is unclear

#### Run-time polymorphism (Dynamic Polymorphism)

Run-time polymorphism is resolved during program execution and is implemented using **inheritance** and **virtual functions**. Unlike **compile-time** polymorphism the exact function invoked depeneds on the **dynamic type of the object** not the static type of the pointer or reference, thie enables:

- Runtime substitution of components
- Plugin-based architectures
- Framework and interface-based design

**Virtual Functions:** A **virtual function** enables dynamic dispatch through a base class pointer or interface

**Example:**

```cpp
#include <iostream>

class Shape {
    public:
        virtual Shape() = default;
        virtual void draw() const {
            std::cout << "Drawing a generic shape" << std::endl;
        }
}

class Circle : public Shape {
    public:
        void draw() const override {
            std::cout << "Drawing a circle." << std::endl;
        }
}
```

**Key Observations**

- Function resolution occurs at runtime via a virtual table **(vtable)**
- Enables behaviour variation withou modifying calling code
- Requires at least one virtual function in the base class
